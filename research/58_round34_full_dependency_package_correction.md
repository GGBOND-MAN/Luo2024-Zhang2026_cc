# Round34 完整依赖包修正说明

日期：2026-09-11

## 1. 问题

旧文件 `round34_final_engineering_upload_20260910_211515.zip` 是增量审查包，只包含新增
`+r34`、R34 实验入口、测试、结果与报告。它没有包含冻结执行身份中的全部继承源码，却没有
在文件名和运行说明中充分标明不能独立运行。

将旧 ZIP 内容与 `round34_final_test_protocol_v1/source_hashes.csv` 逐项比较：

- 冻结身份要求源码：165 个；
- 旧包实际包含：24 个；
- 缺失：141 个；
- 缺失分布：`+fsjad` 45、`+jad` 17、`+r29` 10、`+r30` 19、`+r31` 17、
  `+r32` 17、`+r33` 16。

旧包本身没有修改算法或结果，但不能用于空目录中的独立服务器运行，应只保留为增量历史包。

## 2. 修正原则

新完整包严格按冻结 `source_hashes.csv` 的 165 行逐文件复制，并对每个目标文件重新计算
SHA-256。新包同时包含：

- 完整的 165 个 MATLAB 执行源码；
- R32、R33、R34 的冻结协议与接受身份所需小型结果；
- R34 bootstrap 反例、三输入工程烟雾结果和预检结果；
- research/48–58；
- 实际通过及失败日志；
- 逐文件依赖审计 CSV；
- MATLAB 产品依赖说明。

大型历史 `z/Y`、Round29/Round30 原始结果不进入完整包，因为未来冻结 1400-trial 运行由
设计行和 seed 在线重建观测，不依赖这些历史大型 MAT。`run_round34_engineering_smoke` 若要
再次重放旧三个开发输入，仍需原工程中的 Round30 raw；它不是最终服务器运行的必要入口。

## 3. MATLAB 产品依赖

在 MATLAB R2024b 上对授权、分片、聚合、预检和正式估计入口执行
`matlab.codetools.requiredFilesAndProducts`，确认产品要求为：

1. MATLAB 24.2（R2024b）；
2. Parallel Computing Toolbox 24.2。

依赖分析对 package 动态分派只能识别直接入口，因此源文件完整性以 165 文件冻结清单为准，
不能用该工具返回的直接文件数代替源码清单。

## 4. 授权边界

打包安全检查发现，本机原工程的
`round34_final_test_protocol_v1/FINAL_TEST_AUTHORIZATION.mat` 已于 2026-09-10 21:37:57
生成，内容标记为已批准冻结的 1400-trial 试验。该文件保留在原工程中，不删除、不覆盖，
但它不属于本次“修复服务器依赖”的授权范围。

因此修正后的完整依赖包明确排除该授权文件，也不包含最终 1400 行结果。解压、预检和测试
均不能解除执行门禁；若要真正运行最终试验，必须由用户在后续请求中再次明确授权，并在完整
依赖包内重新生成与当前源码、设计和协议一致的授权文件。
